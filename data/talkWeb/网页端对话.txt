这是我使用这个网站里的功能将排轴内容导出的结果，分析这个json文本包含的信息。
这个 JSON 文件是 《明日方舟：终末地》排轴工具导出的完整规划数据，记录了你创建和编辑的多个战斗轴方案（Scenario）。文件内容非常详细，结构清晰，主要包含以下几大类信息：

一、文件元信息（头部）
json
"timestamp": 1779417773902,
"version": "1.0.0",
"timeUnit": "frame",
"fps": 60,
"activeScenarioId": "sc_hpifdym"
timestamp：导出时间戳（毫秒级 Unix 时间）。

version：导出数据格式版本。

timeUnit / fps：时间单位使用“帧”，每秒 60 帧（常用于精确排轴）。

activeScenarioId：当前激活的方案 ID（最后打开或编辑的是 sc_hpifdym）。

二、全局系统常量（systemConstants）
json
"systemConstants": {
  "maxSp": 300,
  "initialSp": 200,
  "spRegenRate": 8,
  "skillSpCostDefault": 100,
  "linkCdReduction": 0,
  "maxStagger": 280,
  "staggerNodeCount": 1,
  "staggerNodeDuration": 120,
  "staggerBreakDuration": 600,
  "executionRecovery": 100
}
这些是战斗中通用的规则：

SP 相关：最大 SP 300，初始 200，每秒回复 8 点，默认技能消耗 100 SP。

韧性/失衡系统：最大失衡值 280，1 个节点，节点持续 120 帧，破韧持续 600 帧，处决回复 100 点。

四、单个方案（Scenario）的内部结构
以一个方案为例（如 骏卫洛丽塔），包含以下关键字段：

1. 轨道（tracks）
每个 干员 对应一个 track，里面记录该干员的所有 动作序列。

json
"tracks": [
  {
    "id": "ROSSI",   // 干员标识
    "actions": [ ... ],   // 动作列表
    "initialGauge": 0,
    "maxGaugeOverride": null,
    "gaugeEfficiency": 100,
    "weaponId": null,
    "stats": { ... },
    ...
  }
]
2. 动作（actions）类型
每个动作是一个对象，常见类型包括：

攻击（attack）：普通攻击/重击，包含连段序列（attackSegmentIndex）。

战技（skill）：消耗 SP 的技能。

连携（link）：连携技，有冷却时间（cooldown）。

终结技（ultimate）：消耗技力槽（gaugeCost）的大招。

处决（execution）：破韧后的处决动作。

每个动作都包含非常详细的参数：

json
{
  "id": "ROSSI_attack_seg1",
  "type": "attack",
  "name": "重击 1",

  "gaugeGain": 0,

六、特殊机制记录

3. 角色覆盖（characterOverrides）
用于在不修改原始技能定义的情况下，局部调整某个技能的参数（如伤害 tick、sp 获得等）。

完整的数据模型 (Data Schema)

干员与技能的动作库 (Action Library)

文件中包含了大量技能数据，如 ROSSI 的“重击”、“战技”、“连携”等。每个技能的 duration, damageTicks, spCost, gaugeGain 都是宝贵的游戏机制参数。

装备与属性系统框架 (Stats Framework)

weaponId, equipmentAppliedDeltas, gaugeEfficiency 等字段，揭示了游戏内属性是如何通过装备叠加并影响战斗循环的。

核心战斗机制参数 (Game Mechanics Constants)

systemConstants 里的 maxSp, spRegenRate, maxStagger, staggerBreakDuration 等，是整个战斗循环的基础规则，可以直接复用。

❌ 无法直接获得，需要自己开发的部分
前端用户界面 (Frontend UI)

JSON 只包含数据，没有界面代码。你需要从头构建一个交互界面，包括时间轴画布、拖拽操作、干员选择面板等所有可视化元素。

可视化与交互逻辑 (Visualization & Interaction)

数据中的 startTime 和 duration 只是数字。你需要编写代码，将它们渲染为时间轴上的彩色条块，并实现拖拽、缩放、对齐等所有交互功能。

计算引擎 (Calculation Engine)

这是核心难点。你需要根据 systemConstants 和干员的 actions，实时模拟 SP 回复、技力增长、技能冷却等，并确保界面和数据模型的状态始终保持一致。

数据导入/导出功能 (Import/Export)

JSON 文件本身是导出格式。你需要开发功能，让工具能解析你提供的这种 JSON 结构，重建整个场景，同时也要能将当前场景导出为同样格式的文件。

后端与账号服务 (Backend & Account Service)

原网站有“登录”功能，意味着它有后端服务来保存用户数据。如果要复刻完整功能，你需要搭建后端服务器和数据库。
