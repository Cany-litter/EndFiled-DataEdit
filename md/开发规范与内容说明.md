## 3. 后端开发规范

### 3.1 控制器模式

所有控制器继承 `BaseController<T, M extends BaseMapper<T>>`，该基类提供通用 CRUD 实现（不含注解）：

```
BaseController 可用方法：
  defaultAll()       → Result<List<T>>         全量查询
  defaultPage(page, wrapper) → Result<PageResult<T>>  分页查询
  defaultGet(id)     → Result<T>               按 ID 查询
  defaultCreate(t)   → Result<T>               创建
  defaultUpdate(id,t)→ Result<T>               更新
  defaultDelete(id)  → Result<Void>            删除
```

每个具体控制器在自己的类中显式声明 `@GetMapping`/`@PostMapping` 等端点注解：

```java
@RestController
@RequestMapping("/api/v1/characters")
public class CharacterController extends BaseController<GameCharacter, CharacterMapper> {

    @GetMapping
    public Result<PageResult<GameCharacter>> list(
            @RequestParam(defaultValue = "1") Integer page,
            @RequestParam(defaultValue = "20") Integer size) {
        var q = new LambdaQueryWrapper<GameCharacter>();
        return defaultPage(new Page<>(page, size), q);
    }

    @GetMapping("/all")
    public Result<List<GameCharacter>> all() { return defaultAll(); }

    @GetMapping("/{id}")
    public Result<GameCharacter> get(@PathVariable String id) { return defaultGet(id); }

    @PostMapping
    public Result<GameCharacter> create(@Valid @RequestBody GameCharacter c) { return defaultCreate(c); }

    @PutMapping("/{id}")
    public Result<GameCharacter> update(@PathVariable String id, @Valid @RequestBody GameCharacter c) { return defaultUpdate(id, c); }

    @DeleteMapping("/{id}")
    public Result<Void> delete(@PathVariable String id) { return defaultDelete(id); }
}
```

**设计原则**：
- 基类只提供实现，不定义端点——避免 Spring 注解继承问题（特别是复合主键模型）
- 每个控制器覆盖 `list()` 做分页，并额外提供 `/all` 端点做全量查询
- 复合主键模型（CharacterStat、WeaponStat、WeaponAffix、SkillLevel、SkillCost）的 update/delete 使用 `mapper.update(entity, wrapper)` 方式

### 3.2 API 响应格式

所有 API 返回统一包装：

```json
{
  "code": 200,          // 状态码
  "message": "success",  // 提示信息
  "data": ...            // 实际数据
}
```

分页返回特殊格式：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "items": [...],      // 本页数据
    "total": 100,        // 总数
    "page": 1,           // 当前页码
    "size": 20,          // 每页大小
    "pages": 5           // 总页数
  }
}
```

### 3.3 路由版本

所有 API 路由前缀：`/api/v1/`

### 3.4 分页约定

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `page` | 1 | 页码 |
| `size` | 20 | 每页大小 |

前端获取全量数据做查找表时，应调用 `/all` 端点而非 `list()`。

### 3.5 输入验证

- 使用 `javax.validation` 的 `@NotBlank`、`@NotNull` 等注解标注在 model 字段上
- Controller 参数加 `@Valid`
- `GlobalExceptionHandler` 统一处理 `MethodArgumentNotValidException`

### 3.6 异常处理

`GlobalExceptionHandler` 处理以下异常类型：

| 异常 | HTTP 状态码 |
|------|-----------|
| `MethodArgumentNotValidException` | 400 |
| `HttpRequestMethodNotSupportedException` | 405 |
| `Exception` (兜底) | 500 |

## 4. 前端开发规范

### 4.1 API 方法定义

所有 API 方法集中在 `frontend/src/api.ts`，按资源分组为命名空间对象：

```typescript
export const CharacterApi = {
  listAll: () => api.get('/characters/all').then(r => r.data as Character[]),
  list: (name?: string) => api.get('/characters', { params: { name } }).then(r => (r.data as PageResult<Character>).items),
  get: (id: string) => api.get(`/characters/${id}`).then(r => r.data as Character),
  save: (c: Character) => c.id ? api.put(`/characters/${c.id}`, c) : api.post('/characters', c),
  delete: (id: string) => api.delete(`/characters/${id}`),
}
```

**命名规则**：
- `listAll()` — 调用 `/all` 端点，返回全量数据 `T[]`
- `list(params?)` — 调用分页端点，返回 `PageResult.items`（即 `T[]`）
- `get(id)` — 返回单个实体 `T`
- `save(entity)` — 根据有无 ID 自动选择 POST/PUT
- `delete(id)` — 删除

### 4.2 Axios 响应拦截器

```typescript
api.interceptors.response.use(
  res => { res.data = res.data?.data; return res },
  err => Promise.reject(err)
)
```

拦截器自动解包 `Result.data`，因此 `get()`/`save()` 的调用方直接拿到实体对象。

### 4.3 组件模式

- 使用 Vue 3 Composition API (`<script setup lang="ts">`)
- 数据管理页面统一模式：
  - `load()` 函数内调用 `xxxApi.listAll()` 获取表格数据
  - `loading` ref 控制加载状态
  - `dialogVisible` + `editing` 控制编辑弹窗
- 配装编辑器/配队编辑器等页面，查找数据（角色/武器/装备等）使用 `listAll()` 加载全量，客户端过滤
- 不直接调用 `api.get(...)`，统一通过 `xxxApi` 对象

### 4.4 组件引用 Endaxis 代码

Endaxis 源码位于 `reference/endaxis/`（Git Submodule），作为参考阅读无需 import。如需直接复用其中代码，应将其复制到 `frontend/src/` 下对应目录后再进行适配。

## 5. 数据库规范

### 5.1 命名

- 表名：蛇形命名，单数（如 `character`、`weapon_stat`、`gain`）
- 列名：蛇形命名（如 `character_id`、`effect_category`）
- 主键：`id VARCHAR(32) PRIMARY KEY`
- 时间戳：`created_at`、`updated_at`

### 5.2 通用字段

所有表包含：
```sql
`reserve1`  VARCHAR(255) COMMENT '备用1',
`reserve2`  VARCHAR(255) COMMENT '备用2',
`created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
`updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
```

`reserve1`/`reserve2` 为项目保留的通用备用字段，可根据实际用途重命名。例如 Gain 表已经将 `reserve1` 改为 `source_type`、`reserve2` 改为 `source_ref_id`。其他表的 reserve 字段未使用时不改名。

### 5.3 索引

常用查询字段加索引，以 `idx_` 为前缀。例如：
```sql
INDEX `idx_name` (`name`),
INDEX `idx_gain_type` (`gain_type`),
INDEX `idx_effect_category` (`effect_category`)
```

### 7.2 新增一个带参数的筛选查询

后端 Controller：
```java
@GetMapping
public Result<PageResult<T>> list(
        @RequestParam(required = false) String param,
        @RequestParam(defaultValue = "1") Integer page,
        @RequestParam(defaultValue = "20") Integer size) {
    var q = new LambdaQueryWrapper<T>();
    if (param != null) q.eq(T::getField, param);
    return defaultPage(new Page<>(page, size), q);
}
```

前端 api.ts：
```typescript
list: (param?: string) => api.get('/resource', { params: { param } })
    .then(r => (r.data as PageResult<T>).items),
```

## 9. 编码风格

### 9.1 Java

- 缩进：4 空格
- 类名：PascalCase
- 方法/变量：camelCase
- 常量：UPPER_SNAKE_CASE
- 使用 `var` 本地类型推断
- 构造器注入（不使用 `@Autowired`）

### 9.2 TypeScript / Vue

- 缩进：2 空格
- 组件名：PascalCase
- 变量/函数：camelCase
- 常量：UPPER_SNAKE_CASE
- 优先使用 `const` 而非 `let`
- 模板中尽量简洁，复杂逻辑放在 `<script>` 中
- 有类型定义的变量不用 `any`，优先使用 `interface`

### 9.3 CSS

- 使用 scoped style
- 类名：kebab-case
- 避免深层嵌套
- 遵循 BEM 风格命名
