# 配装方案系统说明

## 一、概述

配装方案系统是终末地数据编辑器的核心功能模块，允许用户为角色创建、保存和管理配装方案。系统涵盖前端配装编辑器、配装方案列表、后端 CRUD API，以及集成了 14 乘区伤害模型的属性计算与伤害模拟引擎。

---

## 二、页面列表

| 路由 | 组件 | 页面标题 | 功能 |
|------|------|----------|------|
| `/loadout` | LoadoutEditor.vue | 配装编辑器 | 创建配装方案，实时计算面板属性与技能伤害 |
| `/loadout/:id` | LoadoutEditor.vue | 配装编辑器 | 编辑已有配装方案 |
| `/builds` | LoadoutList.vue | 配装方案 | 方案列表，支持新建/编辑/复制/删除/导出 |

## 三、配装编辑器（LoadoutEditor.vue）

### 3.1 界面布局

单页布局，自上而下分为三个区域：

**顶部行为栏**：
- 方案名称编辑框 + 保存 / 导出 Excel / 返回按钮

**中部 4 列区域**（等宽 flex，`min-width:300px`，窄屏水平滚动）：

| 列：角色与武器 | 列：防具 | 列：配件 | 列：常驻增益 |
|---|---|---|---|
| 角色选择(下拉)<br>角色等级 1-90<br>武器选择(下拉)<br>武器等级 1-90<br>词条1 等级 1-9<br>词条2 等级 1-9<br>词条3 等级 1-9(可展开描述)<br>武器潜能 0-5 | 护甲选择<br>护手选择<br>各 3 属性×精锻 0-3<br>套装激活 badge | 配件1 选择<br>配件2 选择<br>各 3 属性×精锻 0-3 | 常驻增益分组列表<br>开关勾选 |

**底部区域**：
- **面板属性**（分层展示）：最终面板 → 角色基础 → 武器加成 → 装备加成 → 常驻增益加成
- **技能伤害汇总表**：名称 / 等级 / 倍率 / 伤害（无 15 乘区分项明细）

### 3.2 数据流程

```
初始化 onMounted()
  ↓
加载角色列表、增益列表、character_stat(角色等级属性)、weapon_stat(武器等级攻击力)
  ↓  构建 charStatMap/weaponStatMap 查找表
用户选择角色 → onCharChange()
  ↓
加载可用武器、装备(按部位)、技能、技能等级倍率
  ↓
用户选择武器、装备、常驻增益
  ↓  recalc()
读取 charStatMap[c.id + ":" + level] 获取等级属性
构建 charCfg { baseAtk, baseHp, baseStr/Agi/Int/Wil ... }
收集装备副属性 + 精锻等级
  ↓  分层计算
buildBaseLayer(charCfg)  →  角色基础层(base)
buildWeaponLayer(weapon) →  武器加成层(weapon)
equipSubStatsToLayer()   →  装备加成层(equip)
buildGainsLayer()        →  常驻增益层(gains)
computeDerivedFinal()    →  最终面板(final)
  ↓
技能伤害汇总: skillDamageRows
从 final 层取攻击/暴击/爆伤/增伤 → calcDamage() → 汇总伤害
（战斗参数使用内部硬编码默认值，无 UI）
```

### 3.3 面板属性计算

调用 `stats.ts` → `calcFinalStats(char, weapon, equip)`。

#### 3.3.1 完整公式体系（基于游戏实际数据）

| 面板字段 | 计算公式 | 数据来源 |
|---------|---------|---------|
| **攻击力** | `[(baseAtk + weaponAtk) × (1 + atkPercent) + flatBonus] × (1 + attrBonus)` | 角色 + 武器 + 装备 |
| **生命值** | `baseHp × (1 + hpPercent) + flatBonus` | 角色基础 + 武器、装备、增益% |
| **力量** | `(baseStr + trustBonus + weaponBonus + equip.str) × (1 + percentBonus)` | 角色 + 信赖 + 武器匹配 + 装备 |
| **敏捷** | 同上 (trustBonus 受信任等级影响) | 同上 |
| **智识** | 同上 | 同上 |
| **意志** | 同上 | 同上 |
| **能力值对攻击力的百分比加成** | `floor(mainAttr) × 0.005 + floor(subAttr) × 0.002` | 主能力 + 副能力取整 |
| **力量生命加成** | `5 × floor(力量)` | 每1点力量 = 5生命值 |
| **受治疗效率** | `0.001 × floor(意志)` | 意志取整后计算 |
| **物理抗性** | `floor(agi) > 0 ? 100 - 100/(0.001×floor(agi)+1) : 0` | 敏捷取整，最小值0.1 |
| **法术抗性** | `floor(int) > 0 ? 100 - 100/(0.001×floor(int)+1) : 0` | 智识取整，最小值0.1 |
| **暴击率** | 基础5% + 武器、装备、增益提供的暴击率 | 基础5%+武器、装备、增益累加 |
| **暴击伤害** | 基础50% + 武器、装备、增益提供的爆伤 | 基础50%+武器、装备、增益累加 |
| **增伤加成** | 武器、装备、增益提供的所有伤害类型加成之和 | 武器、装备、增益累加 |
| **源石技艺强度** | 武器、装备、增益提供的源石技艺强度之和 | 武器、装备、增益累加 |
| **充能效率** | 武器、装备、增益提供的充能效率之和 | 武器、装备、增益累加 |

#### 3.3.2 属性关联关系详解

**属性加成（核心机制）**：
```
能力值加成 = INT(主能力) × 0.005 + INT(副能力) × 0.002
```
- 主能力每1点 → 攻击力 +0.5%
- 副能力每1点 → 攻击力 +0.2%
- 取整参与计算（如123.70 → 123）

**四维属性→次级属性**：
```
力量 → 生命值加成 = 5 × INT(力量)
敏捷 → 物理抗性点数 = 100 - 100 / (0.001 × INT(敏捷) + 1)
智识 → 法术抗性点数 = 100 - 100 / (0.001 × INT(智识) + 1)
意志 → 受治疗效率 = 0.001 × INT(意志)
```

**基础防御力**：
- 来源于装备的 baseDef 字段（护甲/护手/配件各不相同）
- 70级时：护甲56，护手42，配件21
- **全伤害减免** = 防御力 / (防御力 + 100)
- 部分28/36级装备防御力带小数

**暴击机制**：
- 干员基础暴击率 = 5%，基础暴击伤害 = 50%
- 暴击伤害提升当前仅伊冯终结技 + 天赋[冰点]提供
- 敌人基础暴击率 = 0%

**信赖天赋累计加成**：
| 等级 | 加成 |
|------|------|
| 1 | +10 |
| 2 | +15（累计25） |
| 3 | +15（累计40） |
| 4 | +20（累计60） |

#### 3.3.3 分层属性展示规范

属性面板采用五层叠加展示，顺序从上到下：最终面板 → 角色基础 → 武器加成 → 装备加成 → 常驻增益加成。

**最终面板（final 层）** — 展示全部最终计算值：

| 字段 | 格式 | 公式 |
|------|------|------|
| 攻击力 | 小数2位 | (baseAtk + weaponAtk) × (1 + atkPercent%) × (1 + attrBonus) |
| 生命值 | 小数2位 | baseHp × (1 + hpPercent%) + 5 × floor(str) |
| 防御力 | 整数 | 装备 baseDef 之和 |
| 减伤率 | 百分比 | def / (def + 100) |
| 暴击率 | 百分比 | 基础5% + 各层累加 |
| 暴击伤害 | 百分比 | 基础50% + 各层累加 |
| 伤害加成 | 百分比 | 物理/灼热/电磁/寒冷/自然/超域 + 技能类型(普攻/战技/连携/终结/失衡) 总和 |
| 属性加成% | 百分比 | floor(mainAttr) × 0.005 + floor(subAttr) × 0.002 |
| 力量/敏捷/智识/意志 | 小数2位 | 基础 + 武器 + 装备 + 增益 |
| 物理抗性 | 数值 | floor(agi) > 0 ? 100 - 100/(0.001×floor(agi)+1) : 0 |
| 四元素抗性(灼热/电磁/寒冷/自然) | 数值 | floor(int) > 0 ? 100 - 100/(0.001×floor(int)+1) : 0 |
| 源石技艺强度 | 数值 | 各层累加 |
| 充能效率 | 百分比 | 各层累加 |
| 治疗效率加成 | 百分比 | 各层累加 + 0.1 × floor(wil) |
| 受治疗效率加成 | 百分比 | 各层累加 |

**各分层(base/weapon/equip/gains)** — 仅展示该层贡献的数值（key-value 列表），便于追溯来源。

### 3.4 装备属性合并逻辑

`recalc()` 中遍历 4 个装备槽，对每个部位的三条属性（attr1/attr2/attr3）：

1. 初始化 `equipRefines[key]`（首次选择装备时，默认取装备自身 `attrNRefine` 字段，否则为 0）
2. 按精锻等级（0-3）获取对应值：`refine=0 → Value, 1→V1, 2→V2, 3→V3`
3. 调用 `applyAttr(equip, type, value)` 按类型名匹配合并到 EquipStats 对象

精锻等级通过按钮组交互：每个属性下方展示一行 4 个按钮 `[精锻0] [精锻1] [精锻2] [精锻3]`，点击 `setRefine(key, val)` 直接设置精锻等级，当前选中项高亮（`type="primary"`）。每个部位的三条属性独立维护精锻等级（key 格式：`${slot}r1`/`${slot}r2`/`${slot}r3`）。

装备属性显示使用 `formatPct(val)` 自动格式化数值：绝对值 <1 的小数转换为百分比显示（如 `0.15 → 15%`），≥1 的值保持原样。

#### 3.4.1 装备精锻数值参考（70级）

| 属性类型 | 精锻0 | 精锻1 | 精锻2 | 精锻3 |
|---------|-------|-------|-------|-------|
| 能力值（护甲） | 115 | 126 | 138 | 149 |
| 能力值（护手） | 65 | 71 | 78 | 84 |
| 能力值（配件） | 32 | 35 | 38 | 41 |
| 百分比加成 | 14.4% | 15.84% | 17.28% | 18.72% |

#### 3.4.2 装备副属性(attr3)完整枚举

攻击力、生命值、攻击力%/生命值%、暴击率、暴击伤害、增伤(全属性/各属性)、源石技艺强度、充能效率、主能力%/副能力%、防御力%、治疗效率加成、各技能类型伤害加成、对失衡目标伤害加成、全伤害减免。

#### 3.4.3 类型匹配规则（`toPercent` 自动处理）

| 匹配内容 | 目标字段 | 数值处理 |
|---------|---------|---------|
| 力量/str | equip.str | 直接累加 |
| 敏捷/agi | equip.agi | 直接累加 |
| 智识/int | equip.int | 直接累加 |
| 意志/wil | equip.wil | 直接累加 |
| 攻击力/atk/atk_up | equip.atkPercent | toPercent |
| 生命值/hp | equip.hpPercent | toPercent |
| 防御力/def | equip.defPercent | toPercent |
| 暴击率/crit_rate | equip.critRate | toPercent |
| 暴击伤害/crit_dmg | equip.critDamage | toPercent |
| 增伤/damage_bonus/伤害加成 | equip.damageBonus | toPercent |
| 源石技艺/arts_mastery | equip.artsMastery | toPercent |
| 充能/energy_recharge | equip.energyRecharge | toPercent |

### 3.5 武器词条

- 界面展示使用 `affixNName` 字段（中文名称），而非 `affixNType`（英文 key）
- 数值使用 `formatPct(val)` 格式化：如 `0.39 → +39%`
- 武器词条1（affix1）的 type 与角色的 mainAttr/subAttr 匹配时，对应属性获得 weaponBonus
- 词条2/3 不参与属性计算，仅展示

**词条升阶规则**：
| 武器等级 | 词条1上限 | 词条2上限 |

| 1~20 | Lv.3 | Lv.3 |
| 20~40 | Lv.5 | Lv.4 |
| 40~60 | Lv.6 | Lv.6 |
| 60~80 | Lv.8 | Lv.7 |

词条3等级 = 潜能 + 4（0潜→Lv.4, ..., 5潜→Lv.9）

### 3.8 技能伤害计算

底部展示汇总表（非明细表），按技能行展示：

- 滑块调整技能等级 1-12
- 从 `skillLevelMap` 获取对应等级的 `multiplier/100` 作为倍率
- 从 `layerData.final` 获取面板属性（攻击/暴击/爆伤/全增伤总和）
- 调用 `calcDamage()` 计算最终伤害
- 每行输出：技能名称 / 等级 / 倍率 / 伤害

**战斗参数说明**：不再提供 UI 配置，`battleConfig` 在组件内以硬编码默认值存在：

```js
const battleConfig = {
  targetDef: 100, targetResistance: 0, targetResistanceIgnore: 0,
  isStaggered: false, staggerMultiplier: 1.3,
  baseDamageFlat: 0, comboBonus: 0, specialMultiplier: 1,
  damageReduction: 0, amplifyBonus: 0, weakenReduction: 0,
  shelterValue: 0, fragileBonus: 0, vulnerableBonus: 0,
  nonControlledReduction: 0, targetCount: 1,
  extraCritRate: 0, extraCritDamage: 0, extraDamageBonus: 0,
}
```

**15 乘区公式引擎**（`calcDamage` 内部实现，完整公式见 `已完成功能汇总.md` 六.3 节）：
```
最终伤害 = 基础 × 暴击 × 增伤 × 减伤 × 增幅 × 虚弱 × 庇护
         × 脆弱 × 易伤 × 防御 × 失衡 × 抗性 × 连击 × 特殊
```

### 3.9 保存方案

`saveBuild()` 收集当前选择：

```json
{
  "name": "${角色名}配装方案",
  "characterId": "...",
  "weaponId": "...",
  "armorId": "...",
  "gloveId": "...",
  "accessory1Id": "...",
  "accessory2Id": "...",
  "charLevel": 90,
  "weaponLevel": 90,
  "equipLevel": 70,
  "charPotential": 0,
  "weaponPotential": 0,
  "affix1Level": 1,
  "affix2Level": 1,
  "affix3Level": 1,
  "equipRefines": "{\"armorr1\":0,\"armorr2\":1,...}",
  "selectedGains": "[\"gain_xxx\",\"gain_yyy\",...]"
}
```

新增字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| `charPotential` | int 0-5 | 角色潜能等级 |
| `weaponPotential` | int 0-5 | 武器潜能等级 |
| `affix1Level` / `affix2Level` / `affix3Level` | int 1-9 | 三词条各等级 |

| `selectedGains` | JSON string | 已选常驻增益 ID 列表 |

通过 `BuildApi.save()` → POST（新建）/ PUT（更新）

### 3.10 加载方案

`loadBuild(id)` 在 `onMounted` 中检测路由参数 `:id`：

1. `BuildApi.get(id)` 获取方案数据
2. 查找对应角色 → `onCharChange` 加载依赖数据
3. 回填武器 ID 和 4 个装备槽 ID
4. `recalc()` 刷新面板和伤害

### 3.11 导出 Excel

按当前选中方案导出为 `配装方案_${名称}.xlsx`：

- Sheet「方案信息」：方案名称、角色ID、武器ID、攻击力、生命值、四维、属性加成
- 每个技能一个 Sheet：乘区明细表

## 七、已知差异与待改进项

根据终末地数据编辑器_完整知识库.md、终末地数据导论.md、Endfield_伤害计算分析文档.md 的详细对比分析，当前配装方案界面与游戏实际数据系统之间存在以下差异：

### 7.1 面板属性（已全部实现）

所有面板字段已在分层展示中完整实现并追踪来源，无缺失字段。

### 7.2 界面现状说明

1. **单页布局**：已从双栏改为 4 列顶部 + 底部面板 + 底部伤害表
2. **战斗参数**：已移除 UI，使用内部硬编码默认值（`battleConfig`）
3. **技能伤害表**：仅展示汇总（名称/等级/倍率/伤害），不再展示 15 乘区分项
4. **装备属性值右对齐**：通过 `margin-left:auto` 实现

### 7.3 伤害公式补充

当前 calcDamage 实现与游戏实际数据的差异：

1. **防御区公式**：当前实现 `1 - def/(def+100)`，NGA帖确认应使用 `100/(def+100)`。两者在def=100时结果一致（均为0.5），但公式形态不同
2. **敌人抗性**：当前实现 `1 - resistance/100 + ignore/100`，与 NGA帖一致 ✅
3. **连击增伤层数**：当前仅区分 chain 类型+0.3，未实现完整连击层数系统（1-4层，每层不同倍率，非线性叠加）
