# 代码分析及重构计划 - 排轴伤害计算

## 一、参考项目分析：编队总伤计算器

### 1.1 项目概况

- **语言/框架**：原生 JavaScript (ES6 Module)，无框架，无构建工具
- **目标**：浏览器端《明日方舟：终末地》队伍总伤害计算器
- **架构**：纯数据驱动 — 角色/武器/装备/增益/Buff 全部以 JSON 定义，引擎自动适配

### 1.2 核心架构

```
数据 JSON → data-loader.js → 内存数据 → team-app.js (编排)
                                         ├─ stats.js (属性计算)
                                         ├─ engine.js (伤害计算引擎)
                                         ├─ team-grid.js (排轴网格 UI)
                                         └─ team-palette.js (Buff 面板 UI)
```

### 1.3 伤害计算引擎 (engine.js)

#### 分类驱动计算

```
categories = [
  { key: "DMG_Dealt",      label: "增伤" },
  { key: "DMG_Taken",      label: "易伤" },
  { key: "Susceptibility", label: "脆弱" },
  { key: "Arts_Amp",       label: "增幅" },
  { key: "Resistance",     label: "抗性" },
  { key: "Link",           label: "连击" },
  { key: "Staggered",      label: "失衡" },
  { key: "Finisher",       label: "处决" },
  // ... 角色特有分类
]
```

计算流程：

```
阶段1: 总攻击力 = ((基础攻击 + 武器攻击) × (1 + 攻击力%) + 固定攻击力) × (1 + 属性加成%)
阶段2: 技能伤害 = 倍率 × 总攻击力 × ∏(1 + 各伤害乘区)
```

各乘区计算：

```
每个分类 multiplier = 1 + Σ(effects) × Π(metaMultipliers)
最终伤害 = baseDamage × Π(allCategoryMultipliers)
```

#### Buff 效果解析 (resolveEffectValue)

四种模式：

| 模式 | 数据格式 | 公式 |
|------|---------|------|
| 固定值 | `{ value: 0.2 }` | `value` |
| 线性缩放 | `{ scaleStat, scaleRatio, scaleCap? }` | `min(stat × ratio, cap)` |
| 分段线性曲线 | `{ scaleStat, scaleCurve: [[x0,y0],...] }` | `piecewiseLinear(stat, curve)` |
| 饱和缩放 | `{ value, saturationScale: { stat, x, y, z } }` | `value × (x + y × stat / (z + stat))` |

#### 条件系统 (matchesCondition)

Buff 效果可基于以下条件过滤：
- `skillType`: 匹配技能类型（普攻/战技/连携/终结/异常等）
- `element`: 匹配元素类型（物理/灼热/寒冷/电磁/自然）

#### 暴击系统 (collectCrit)

```
critRate = min(max(baseCritRate + Σ(critRateBuff), 0), 1)
critDamage = baseCritDamage + Σ(critDamageBuff)
expectedMultiplier = 1 + critRate × critDamage
```

#### 特殊机制

- **Buff 替换 (applyBuffReplacements)**：高版本 Buff 通过 `replaces` 字段自动替换低版本
- **技能覆盖 (applySkillOverrides)**：Buff 可修改技能倍率、元素类型、添加伤害判定帧
- **源石技艺强度曲线**：分段线性插值 `(0,1) → (500,6)`

### 1.4 属性系统 (stats.js)

#### 攻击力公式

```
totalAtk = ((baseAtk + weaponAtk) × (1 + ΣatkPercent) + ΣflatAtk) × (1 + statAtkBonus)
statAtkBonus = 主属性×主比例 + Σ(副属性×副比例) + ΣextraStatAtk
```

#### 属性总值计算 (calculateStatTotals)

```
totals = { ...baseStats }
+ { 装备 statBonuses + 词条(主词条→主属性，副词条→副属性) }
+ { 武器固定属性 + 词条 }
+ { 装备/武器词条百分比 → pendingPercent }
最后: applyPercentBonuses(totals, pendingPercent)
```

#### Buff 属性加成 (applyBuffStatBonuses)

Buff 可携带 `statBonuses` / `mainAffix` / `subAffixes` / `allAffix`，在装备属性基础上额外累加。

### 1.5 数据模型

#### 角色数据
```json
{
  "id": "string", "name": "string",
  "baseAtk": number, "baseCritRate": number, "baseCritDamage": number,
  "baseStats": { "strength": number, "agility": number, "intellect": number, "will": number },
  "statConfig": { "primary": { "stat": string, "ratio": number }, "secondary": [...] },
  "weaponType": string,
  "skills": [{ "name": string, "type": string, "hits": [{ "element": string, "multiplier": number|number[] }] }],
  "uniqueBuffs": [ Buff ],
  "potentialBuffs": [ Buff[] ]
}
```

#### Buff 数据
```json
{
  "id": string, "name": string, "optional": boolean, "scope": "team",
  "replaces": string|string[],
  "statBonuses": { strength: number, ... },
  "mainAffix": { "flat": number, "percent": number },
  "subAffixes": [{ "flat": number, "percent": number }],
  "effects": [{
    "category": string, "value": number|number[],
    "condition": { "skillType"?: string|string[], "element"?: string|string[] },
    "scaleStat"?: string, "scaleRatio"?: number, "scaleCap"?: number,
    "scaleCurve"?: [[number,number],...],
    "saturationScale"?: { "stat": string, "x": number, "y": number, "z": number }
  }],
  "metas": [{ "category": string, "multiplier": number, "condition"?: {...} }],
  "skillOverrides": [{ "skillIndex"?: number, "skillId"?: string, ... }]
}
```

## 二、主项目分析：EndFiled

### 2.1 当前架构

```
前端 Vue 3 + TS → 引擎 (engine/formulas/*, engine/simulation/*)
                → API → Spring Boot 后端 → MySQL
```

### 2.2 伤害计算现状

#### damage.ts — calcDamage()
```typescript
export interface DamageInput {
  attack: number, skillMultiplier: number, baseDamageFlat: number,
  critRate: number, critDamage: number,
  damageBonus: number, damageReduction: number[],
  amplifyBonus: number, weakenReduction: number[],
  shelterValue: number, fragileBonus: number, vulnerableBonus: number,
  defense: number, isTrueDamage: boolean,
  isStaggered: boolean, staggerMultiplier: number,
  resistance: number, resistanceIgnore: number,
  nonControlledReduction: number, comboBonus: number, specialMultiplier: number,
}
```

- 15 个硬编码乘区字段
- 新增乘区需要修改：`DamageInput` + `DamageBreakdown` + `calcDamage()` + 所有调用方
- 无动态分类 / Buff 分组能力

#### stats.ts — StatLayer 系统
- 50+ 属性键，按分类组织 (STAT_DEFS)
- `GAIN_TO_STAT` 映射后端增益数据
- 两层计算：`calcFinalStats()` (简化版) + `computeDerivedFinal()` (分层完整版)

#### attack.ts — calcAttack()
```
raw = (baseAtk + weaponAtk) × (1 + percentBonus) + flatBonus
attrBonus = 1 + floor(mainAttr) × 0.005 + floor(subAttr) × 0.002
return raw × attrBonus
```
与参考项目公式一致。

#### anomaly.ts — 异常伤害
- 法术异常：`baseMultiplier × (1 + anomalyLevel) × 法术等级系数 × 源石技艺强度区`
- 物理异常：`baseMultiplier × stackMult × 物理等级系数 × 源石技艺强度区`
- 与参考项目算法一致

### 2.3 模拟引擎现状

#### teamEngine.ts — 团队循环模拟
- 使用平面 `SimulationConfig`，所有乘区为团队级统一值
- 无 per-skill / per-hit 条件 buff
- 无动态 buff 收集
- 不会根据技能类型/元素类型过滤 buff 效果
- 不支持分类驱动计算

#### timeSimEngine.ts — 时间线模拟
- 仅跟踪 SP / 连击量表 / 失衡值
- **不计算实际伤害**
- 伤害判定帧只记录 `stagger` 值，不输出伤害数值

### 2.4 前端组件现状

| 组件 | 问题 |
|------|------|
| `DpsCalculator.vue` | 使用 `atk × multiplier / 100 × count` 的简化公式，无完整乘区计算 |
| `TeamSimulator.vue` | 使用 `runTeamSimulation()` + 平面配置，buff 选择为虚拟字符串 |
| `DamageDetail.vue` | 大多数乘区使用硬编码默认值 |
| `DpsOverview.vue` | 通过 `timeSimEngine` 聚合但不计算实际伤害 |

### 2.5 主要差距

| 维度 | 参考项目 | 当前项目 |
|------|---------|---------|
| 乘区定义 | 数据驱动（数组） | 硬编码（接口字段） |
| Buff 效果 | 4 种缩放模式 + 条件 | 简单扁平值 |
| 计算粒度 | per-hit 级分类拆解 | 整体计算 |
| Buff 替换 | 支持 replaces | 无 |
| 技能覆盖 | 支持倍率/元素/判定帧覆盖 | 无 |
| 条件过滤 | skillType + element | 无 |
| 暴击处理 | 从 Buff 动态收集 | 预计算传值 |

## 四、关键设计决策

### 4.1 兼容策略

- 不删除/修改现有 `calcDamage()` 和 `DamageInput`
- `calcDamageByCategories()` 作为并行实现
- 各组件逐步迁移至新实现

### 4.2 Buff 数据流

```
数据库 Gains → GAIN_TO_STAT 映射 → StatLayer (属性层)
           ↘ effectCategory → EffectDef[] (效果定义)
```

### 4.3 与时间线的集成

```
TimelineAction.damageTicks[] → 每个 tick 触发伤害计算
                               ↓
                        当前角色 stat + buff 快照
                               ↓
                        calcDamageByCategories()
                               ↓
                        DamageBreakdown → UI 显示
```

### 4.4 状态管理

- 演算状态（SP、连击量表、失衡）由 `timeSimEngine` 维护
- Buff 状态由 Pinia store 或组件维护
- 伤害计算为纯函数，不依赖外部状态
