### 2.2 关键决策：计算引擎放前端还是后端？

**推荐方案：核心计算引擎放在前端（TypeScript）**

理由：
1. 伤害计算需要**实时反馈**——用户调整配装时面板即时更新，每次请求后端延迟不可接受
2. 公式计算无需依赖数据库，纯数学运算
3. 排轴模拟需要在浏览器端进行多次对比计算
4. 后端承担数据持久化和方案共享职责即可

计算引擎模块划分：
```

│   ├── stats.ts        # 面板属性计算

│   ├── anomaly.ts      # 法术异常/爆发伤害
```

#### 计算引擎实现顺序

```
  │
```

#### 反应引擎的核心数据结构

```typescript
// 敌人当前状态
interface EnemyState {
  attachments: Map<ElementType, number>;  // 法术附着类型 → 层数
  attachmentDuration: number;              // 剩余时间
  breakArmor: number;                      // 破防层数
  breakArmorDuration: number;
  isFrozen: boolean;
  isStunned: boolean;                      // 失衡状态
}

// 反应触发结果
interface ReactionResult {
  type: ReactionType;                      // 导电/腐蚀/燃烧/冻结/碎冰/爆发
  damage: number;                          // 额外伤害
  newState: EnemyState;                    // 新状态
  appliedDebuffs: Debuff[];               // 施加的 debuff
}
```

#### 排轴引擎核心逻辑

```typescript
class TimelineSimulator {
  private timeline: TimelineEvent[];
  private state: BattleState;              // 全队状态 + 敌人状态 + 资源
  
  execute(): SimulationResult {
    const sorted = this.timeline.sort((a, b) => a.time - b.time);
    for (const event of sorted) {
      // 1. 时间推进（技力回复）
      this.advanceTime(event.time);
      // 2. 检查技能可用性（CD/能量）
      this.validateEvent(event);
      // 3. 计算技能伤害
      const damage = this.calcDamage(event);
      // 4. 处理附着/破防变化
      this.applyStatusChanges(event);
      // 5. 触发异常反应
      const reactions = this.checkReactions(event);
      // 6. 记录结果
      this.recordResult(event, damage, reactions);
    }
    return this.buildReport();
  }
}
```

### 优先实现的计算引擎模块

建议**第一时间**实现的核心公式模块（放在 `engine/formulas/`）：

1. `attack.ts` - 攻击力公式：`[(基础+武器)×(1+百分比)+固定]×(1+能力值加成)`
2. `damage.ts` - 15 乘区的框架：定义所有乘区接口，每个乘区独立函数
3. `stats.ts` - 面板属性汇总

公式引擎的设计要点：
- 每个乘区用独立函数实现，方便单元测试
- 支持"开关"：常驻增益开启/关闭，方便用户对比
- 输出每个乘区的数值明细，用于前端展示

## 4. 风险和注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 公式频繁更新（游戏版本迭代） | 计算逻辑需要持续维护 | 公式独立成模块，配置化参数 |
| 角色技能数据量大（每个角色独立曲线） | 数据录入工作量大 | 提供 Excel 批量导入 |
| 时间轴编辑器交互复杂度高 | 开发周期长 | 先实现基础的 JSON 编辑，再迭代可视化 |
| 反应系统状态管理复杂 | bug 率高 | 用有限状态机设计，写完整单元测试 |
