## 1. 数据源对比

### AKEDatabase（推荐 ✅）

| 维度 | 详情 |
|------|------|
| 类型 | 纯前端项目，所有数据为**结构化 JSON** |
| 数据范围 | 角色、武器、装备、敌人、物品、成就、副本、活动、地图 |
| 格式 | 每个实体一个独立 JSON 文件 + manifest.json 索引 |
| 质量 | 由 bot 自动从游戏客户端提取，**与游戏数据同步** |
| 最新 | 版本 CN_WIN_REL_1.2.4，最后更新 2026/5/17 |
| 协议 | AGPL-3.0（需开源） |
| 地址 | `https://github.com/nagiyume/AKEDatabase` |

### Warfarin Wiki（❌ 不推荐直接作为数据源）

| 维度 | 详情 |
|------|------|
| 类型 | HTML 页面，**非结构化** |
| 数据范围 | 干员、武器、敌人、设备、物品、装备、教学 |
| 提取方式 | 需爬虫解析 HTML，易碎 |
| 用途 | 作为**公式/机制理解**的参考（已通过 NGA 帖子完成） |

### 关键 JSON 结构示例

**角色 (character)**: `chr_0005_chen.json`
```json
{
  "charId": "chr_0005_chen",
  "name": "陈千语",
  "charType": "物理",
  "rarity": 5,
  "weapontype": "单手剑",
  "profession": "近卫",
  "mainAttrType": "敏捷",
  "subAttrType": "力量",
  "charBattleTag": ["击飞", "失衡"],
  "talents": [{ "name": "斩锋", "values": { "atk": 0.04, ... } }],
  "potentials": [{ "name": "绝影", "values": { "extra_dmg": 0.2, ... } }],
  "growth": { "力量": [...], "敏捷": [...], "生命值": [...], "攻击力": [...] },
  "skill": {
    "chr_0005_chen_NormalSkill": {
      "name": "归穹宇",
      "values": { "atk_scale": [1.69, 1.86, ..., 3.8], "costValue": [100,...] }
    }
  }
}
```

> 角色数据亮点：**growth** 字段包含每级的基础能力值（力量/敏捷/智识/意志/生命/攻击力），**skill** 字段包含技能每级的倍率、CD、消耗。

**武器 (weapon)**: `wpn_sword_0005.json`
```json
{
  "weaponId": "wpn_sword_0005",
  "title": "钢铁余音",
  "rarity": 5,
  "weapontype": 1,           // 1=单手剑
  "baseAtk": [42, 46, ..., 411],  // 1~90级攻击力
  "skilllist": [              // 3个词条
    { "skillName": "敏捷提升·中", "blackboard": [{ "key": "agi", "value": [16,28,...,124] }] },
    { "skillName": "物理伤害提升·中", "blackboard": [...] },
    { "skillName": "巧技·旧火余音", "blackboard": [...] }
  ]
}
```

> 武器亮点：**baseAtk** 数组包含 1~90 级每级攻击力（90 个值），**skilllist** 的数值按词条等级 1~9 排列。

**装备 (equip)**: `suit_atk01.json`
```json
{
  "suitID": "suit_atk01",
  "套组名称": "阿伯莉遗声",
  "value": { "dmg_up": 0.24, "atk_up": 0.05, "duration": 15 },
  "equip": {
    "item_equip_t3_suit_atk01_body_01": {
      "name": "阿伯莉重甲",
      "部位": "护甲",
      "主词条": { "desc": "防御力", "value": 40 },
      "副词条": {
        "词条1": { "desc": "力量", "value": [61,61,61,61] },
        "词条2": { "desc": "敏捷", "value": [41,41,41,41] },
        "词条3": { "desc": "所有技能伤害提升", "value": [0.098,0.098,0.098,0.098] }
      }
    }
  }
}
```

> 装备亮点：每套装一个文件，内含所有部位（护甲/护手/配件），副词条 value 数组长度为 4（0~3 精锻）。

## 3. 推荐接入方案

### 方案一：git submodule（推荐）

```
步骤：
1. 将 AKEDatabase 作为 git submodule 添加到项目
2. 后端启动时 / 前端构建时直接读取 JSON 文件
3. 映射到自己的 TypeScript 类型

项目结构：
endfiled-edit/
├── backend/
├── frontend/
│   ├── src/
│   │   ├── engine/
│   │   └── data/            # 游戏数据
│   │       └── akedb/       # git submodule 链接到 AKEDatabase
│   │           └── public/CH/
│   └── ...
└── data/
    └── akedatabase/          # 或者放在项目根目录
        └── public/CH/
```

### 方案二：构建时从 raw GitHub 拉取

```
步骤：
1. 编写一个脚本，构建时从 raw.githubusercontent.com 拉取 JSON
2. 缓存到本地
3. 适用于不想引入 submodule 的场景

脚本示例思路：
- 读取 weapon/manifest.json → 获取所有武器文件名和路径
- 遍历下载每个武器 JSON
- 同理处理 character、equip、enemy 等
```

### 方案三：运行时动态加载

```
步骤：
1. 后端提供代理 API：/api/data/characters, /api/data/weapons
2. 后端启动时从 JSON 文件加载到内存或 MySQL
3. 前端通过 API 获取数据

优点：数据变更只需重启后端
缺点：需要额外维护数据同步
```

**实际实施方案：方案二（构建时从 raw GitHub 拉取）**

为避免影响克隆项目的其他开发者，最终采用方案二而非方案一。已创建以下脚本：

| 脚本 | 路径 | 说明 |
|------|------|------|
| `fetch-akedb.js` | `scripts/fetch-akedb.js` | 从 raw.githubusercontent.com 拉取 JSON，带缓存 |
| `map-akedb.js` | `scripts/map-akedb.js` | 将原始 JSON 映射为应用数据格式 |
| `import-akedb.js` | `scripts/import-akedb.js` | 将 mapped JSON 写入 MySQL（映射到 DDL 9 张表） |

一套完整流程：
```bash
npm run fetch   # 1. 拉取原始数据
npm run map     # 2. 映射为应用数据
npm run import  # 3. 导入 MySQL
```

### 字段映射

AKEDatabase 的 JSON 字段 → 我们的数据模型。例如角色：

| 我们的字段 | AKEDatabase 字段 | 说明 |
|-----------|-----------------|------|
| `角色ID` | `charId` | |
| `角色名称` | `name` | |
| `稀有度` | `rarity` | 4~6 |
| `可用武器类型` | `weapontype` | 中文名，如"单手剑" |
| `职业` | `profession` | 中文名，如"近卫" |
| `主能力` | `mainAttrType` | 如"敏捷" |
| `副能力` | `subAttrType` | 如"力量" |
| `基础力量` | `growth.力量[等级-1]` | 数组索引 = 等级 - 1 |
| `基础攻击力` | `growth.攻击力[等级-1]` | |
| `基础生命值` | `growth.生命值[等级-1]` | |
| `潜能` | `potentials` | 数组长度 = 可解锁的潜能数 |
| `技能倍率` | `skill.*.values.atk_scale` | 数组，12 个值对应 1~12 级 |
| `技能消耗` | `skill.*.values.costValue` | 大部分为 100 |
| `技能CD` | `skill.*.values.coolDown` | 连携技/终结技有 CD |
| `法术异常系数` | `growth.法术异常伤害系数` | 每级对应的等级系数 |
| `物理异常系数` | `growth.物理异常伤害系数` | 每级对应的等级系数 |

```
更新流程：
1. NagiYume 的 bot 从游戏客户端提取数据 → 更新 GitHub

3. 启动项目即可使用新数据

频率：游戏版本更新时操作，约每月 1~2 次
```

## 5. 补充数据源: extracted JSON

`data/extracted/` 目录包含手动提取的游戏战斗数据（2个JSON文件）：

### 5.1 attack_segments.json
25 个角色的普攻分段数据。每个角色5段(segment_index 0~4)，每段含：
- `duration`：动画时长(秒)
- `gauge_gain`：连携量表获取
- `allowed_types`：允许触发的异常类型列表
- `damage_ticks[]`：伤害判定帧(offset/stagger/sp)
- `anomalies[]`：异常效果

已导入 `attack_segment` + `attack_segment_tick` 表。

### 5.2 skill_actions.json
各技能的动作参数。键名格式 `{CHARACTER_ID}_{type}`：
- `skill`：战技，`link`：连携技，`ultimate`：终结技
- `execution`：处决攻击，`variant_0~6`：变体
- 每个技能含 `duration/cast_time/sp_cost/gauge_gain/cooldown/allowed_types`
- `damage_ticks[]`：伤害帧，`anomalies[]`：异常组

已导入 `skill_action` + `skill_damage_tick` + `skill_anomaly` 表。

## 6. 补充数据源: 华法琳Wiki (TXT)

`data/华法琳Wiki/` 目录包含通过网页抓取的Wiki文本数据，用于补全AKEDatabase缺失的丰富内容。

### 6.1 角色文本 (26个文件)
每个文件含以下章节，通过 `scripts/import_all_data.py` 解析：
- **总览**：英文名、简介、特点、配音演员(JP/EN/CN/KR)、系统推荐武器
- **干员升级**：精英化一至四材料消耗
- **天赋**：被动天赋名+突破阶段效果
- **潜能**：1-5潜的名称和效果
- **后勤技能**：基建技能(解锁阶段+效果)
- **干员情报**：阵营/种族/专长/爱好
- **档案**：基础档案+档案资料一至四
- **语音记录**：全语音文本(战备/战斗/基建/信赖等)

已导入：`character_archive`(127行)、`character_voice`(2070行)、`character_potential`(130行)、`character_promotion`(104行)、`character_logistics`(100行)、`character_profile`(102行)

### 6.2 武器文本 (67+个文件)
- **属性**：等级1-90的逐级攻击力
- **经验消耗**：每级消耗经验值(90级)
- **折金票消耗**：每级消耗折金票(90级)
- **升阶**：阶段0-4的材料需求
- **武器技能**：3个技能(力量提升·小/大等)，每级Rank数值1-9
- **描述**：武器背景故事

已导入：`weapon_level_cost`(6030行)、`weapon_ascension`(~7648行)、`weapon_skill`(196行)、`weapon_skill_rank`(1764行)

### 6.3 装备文本 (22个套组)
- 套组ID(suit_xxx)映射
- 3件套效果描述
- 每套3~4个部件(护甲/护手/配件)，各含防御力、精炼Lv.1~Lv.4属性

已导入：`equipment_set`(22行)

---

> **结论**: AKEDatabase 的 JSON 数据是核心结构化数据源, extracted JSON 补充战斗参数, 华法琳Wiki 补全角色详情/武器消耗/装备套组。三源合一通过 `scripts/import_all_data.py` 完成全部导入。
