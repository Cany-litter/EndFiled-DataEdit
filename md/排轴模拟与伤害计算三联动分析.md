# 排轴模拟与伤害计算 — 三联动重构分析

## 概述

本文档分析三个系统的联动方案：
1. **时间线伤害联动** — timeSimEngine 中 damage_tick 调用完整伤害公式
2. **循环排轴联动** — TeamSimulator 旋转结果与时间线可视化互通
3. **配队数据联动** — 角色/武器/装备/Buff 数据贯通至时间线伤害计算

### 1.2 关键断裂点

| 断裂点 | 现状 | 影响 |
|--------|------|------|
| **角色属性** | TimelineEditor 加载角色，但不计算攻击力/暴击等属性 | 时间线上的技能无法得知角色实时属性 |
| **Buff 效果** | 时间线有 Buff 位置，但 Buff 数据格式简单，无法解析为伤害乘区 | Buff 仅用于位置追踪，不影响伤害计算 |
| **伤害计算** | 只有 staggerEngine 处理时间线事件，但不计算 HP 伤害 | TimeSimEngine 的 `hpDamage` 字段始终为空 |
| **数据模型** | `DamageTick` 有 `hpDamage` 字段但从未填充 | 前端无法显示时间线上的伤害数值 |
| **循环联动** | TeamSimulator 的旋转无法导入时间线；反之亦然 | 用户需在两套系统间手动同步数据 |
| **DPS 计算器** | 使用 `atk * multiplier / 100 * count` 的简化公式 | 结果不可靠，与正式公式脱节 |

## 三、联动一：时间线伤害联动

### 3.1 现状

`timeSimEngine.ts` (214 行) 当前功能：

- 构建事件队列（action_start / action_end / damage_tick）
- 按时间推进处理事件
- 跟踪 SP / 连击量表 / 失衡值
- **不计算实际伤害**
- `DamageTick.hpDamage` 字段存在但从未写入

```typescript
// 当前 timeSimEngine 处理 damage_tick 的代码（简化）:
if (ev.type === 'damage_tick') {
  state.stagger += dt.stagger     // ✅ 处理失衡
  state.sp += dt.sp                // ✅ 处理 SP
  // ❌ 未计算 hpDamage
  events.push({ time: t, type: 'damage_tick', value: dt.stagger /* 非伤害值 */ })
}
```

### 3.2 目标设计

每个 `damage_tick` 事件执行完整伤害计算：

```
damage_tick 触发
    │
    ├── 获取角色属性: CharStatsCache[charId]
    │     ├── attack (总攻击力)
    │     ├── critRate, critDamage
    │     ├── 四维属性 (用于 buff 缩放)
    │     └── 元素加成等
    │
    ├── 获取当前 Buff 快照: BuffActiveCache[charId][currentTime]
    │     ├── 自身 Buff (从 buff 轨道获取)
    │     ├── 团队 Buff (从其他角色 scope:team 获取)
    │     ├── 敌人 Debuff (从 enemyBuffs 获取)
    │     └── 食物/场地 Buff (全局)
    │
    ├── 获取当前状态:
    │     ├── 是否处于失衡 break (staggered → 1.3x)
    │     ├── 当前连击层数 (comboCount → 查连击增伤表)
    │     └── 技能类型 (skillType: normal/skill/chain/ultimate)
    │
    ├── 获取敌人属性:
    │     ├── defense (防御)
    │     ├── resistance (抗性)
    │     └── 当前异常状态
    │
    └── 调用 calcDamageByCategories():
          baseDamage = attack × skillMultiplier
            ↓
          categories 连乘 = Π(1 + eachCategory)
            ↓
          × artsMultiplier (if status type, 查 ARTS_INTENSITY_CURVE)
            ↓
          × defenseMultiplier (100 / (def + 100))
            ↓
          × critMultiplier (1 + critRate × critDamage)
            ↓
          × staggerMultiplier (1.3 if staggered else 1)
            ↓
          × comboMultiplier (查 连击增伤Map)
            ↓
          finalDamage → 写入 events + 累加 totalDamage
```

### 3.4 引擎改造方案

```typescript
// timeSimEngine.ts — 改造架构

// 1. 新增配置参数
interface DamageSimConfig extends SimConfig {
  charSnapshots: Record<string, CharSimSnapshot>  // 角色属性快照
  buffSchedule: ActiveBuffSnapshot[]               // Buff 时间表
  enemyConfig: EnemyDamageConfig                   // 敌人属性
  categories: CategoryDef[]                        // 乘区分类定义
}

// 2. 改造事件队列（在原有基础上增加伤害计算）
interface ScheduledEvent {
  time: number
  type: 'action_start' | 'action_end' | 'damage_tick' | 'buff_start' | 'buff_end'
  action?: SimAction
  tickIndex?: number
  buff?: ActiveBuffSnapshot
}

// 3. 新增伤害计算步骤（在 damage_tick 处理中）
function processDamageTick(
  state: SimState,
  action: SimAction,
  tickIndex: number,
  time: number,
  config: DamageSimConfig,
): DamageEvent {
  // 3a. 获取角色属性
  const charStats = config.charSnapshots[action.charId]
  if (!charStats) return null

  // 3b. 获取该时刻活跃 Buff
  const activeBuffs = getBuffAtTime(config.buffSchedule, action.charId, time)

  // 3c. 获取技能倍率
  const dt = action.damageTicks[tickIndex]
  const multiplier = dt.damageMultiplier ?? action.skillMultiplier ?? 1

  // 3d. 构建 context
  const context = {
    skillType: action.actionType,
    element: action.element,
    statTotals: charStats.stats,
  }

  // 3e. 计算攻击力（含 Buff 中的 atkPercent/flatAtk）
  const atkResult = calculateAtk(charStats, activeBuffs, context)
  const effectiveBase = multiplier * atkResult.totalAtk

  // 3f. 分类驱动计算
  const { finalDamage, breakdown } = calculate(
    effectiveBase, activeBuffs, config.categories, context,
  )

  // 3g. 暴击
  const crit = collectCrit(activeBuffs, context,
    charStats.stats.critRate, charStats.stats.critDamage)

  // 3h. 防御减免
  const defMult = config.enemyConfig
    ? 100 / (config.enemyConfig.defense + 100)
    : 0.5

  // 3i. 失衡加成
  const staggerMult = state.staggered ? 1.3 : 1

  // 3j. 连击增伤
  const comboMult = getComboMultiplier(state.comboCount, action.actionType)

  // 3k. 源石技艺强度（异常技能）
  let artsMult = 1
  if (action.actionType === 'status') {
    artsMult = piecewiseLinear(
      charStats.stats.artsPower, ARTS_INTENSITY_CURVE,
    )
  }

  // 3l. 最终伤害
  const final = finalDamage * defMult * crit.expectedMultiplier
    * staggerMult * comboMult * artsMult

  return {
    time, charId: action.charId,
    actionName: action.name,
    skillType: action.actionType,
    element: action.element,
    baseDamage: effectiveBase,
    breakdown,
    finalDamage: final,
    critMultiplier: crit.expectedMultiplier,
    defenseMultiplier: defMult,
    staggerMultiplier: staggerMult,
    comboMultiplier: comboMult,
    artsMultiplier: artsMult,
    comboLevel: state.comboCount,
    isStaggered: state.staggered,
    buffContributions: extractBuffContribs(breakdown),
  }
}
```

### 3.5 连击层数追踪

```typescript
// 在 SimState 中新增：
interface SimState {
  // ... 现有字段
  combo: {
    count: number           // 当前连击层数 (1-4)
    lastActionTime: number  // 上次动作时间
    decayTimer: number      // 衰减计时器
  }
}

// 处理逻辑：
function updateCombo(state: SimState, now: number, actionType: string) {
  // 连击维持窗口 (例: 3 秒内连续动作维持连击)
  const COMBO_WINDOW = 3
  if (now - state.combo.lastActionTime <= COMBO_WINDOW) {
    state.combo.count = Math.min(state.combo.count + 1, 4)
  } else {
    state.combo.count = 1  // 超时重置
  }
  state.combo.lastActionTime = now
}

// 连击增伤查询：
const 连击增伤Map = {
  1: { skill: 0.3, ultimate: 0.2 },
  2: { skill: 0.45, ultimate: 0.3 },
  3: { skill: 0.6, ultimate: 0.4 },
  4: { skill: 0.75, ultimate: 0.5 },
}

function getComboMultiplier(level: number, type: string): number {
  const entry = 连击增伤Map[level]
  if (!entry) return 1
  const bonus = type === 'ultimate' ? entry.ultimate : entry.skill
  return 1 + bonus
}
```

## 四、联动二：循环排轴联动

### 4.1 现状

两个独立系统：

| 维度 | TeamSimulator | TimelineEditor |
|------|--------------|----------------|
| 数据结构 | `RotationStep[]` | `Track[]` → `TimelineAction[]` |
| 动作定义 | `{ skillId, skillType, label, charIndex }` | `{ id, name, type, element, duration, startTime, damageTicks, ... }` |
| 时间表达 | 顺序队列（隐式时间） | 显式 startTime + duration |
| 重复表达 | 隐式（循环队列） | 显式（列表中有重复元素） |
| 伤害计算 | `teamEngine` (平面配置) | `staggerEngine` (仅失衡) |

### 4.2 目标设计

#### 4.2a 旋转 → 时间线 导入


```typescript
// 新增：时间线 Buff 管理器

class TimelineBuffManager {
  // 角色 Buff 时间表: charId → [{ time, buff, source }]
  private buffSchedule: Map<string, ActiveBuffSnapshot[]>

  // 团队 Buff 缓存
  private teamBuffs: ActiveBuffSnapshot[]

  /** 从时间线 Track 构建 Buff 时间表 */
  buildFromTracks(
    tracks: Track[],
    allCharBuffs: Map<string, Buff[]>,   // 角色固有 Buff
    permanentGains: Gain[],              // 永久增益
    enemyBuffs: Record<string, TimelineAction[]>, // 敌人减益
  ): void {
    // 1. 遍历每个角色的 buff track
    // 2. 解析 buff 轨道上的每个 TimelineAction →
    //    → 将动作数据映射为 ActiveBuffSnapshot
    // 3. 合并永久增益（展开至整个时间线）
    // 4. 合并团队增益（来源其他角色的 scope:team buff）
    // 5. 合并敌人减益（按时间区间展开）
    // 6. 按 charId + startTime 排序
  }

  /** 获取某时刻活跃的 Buff */
  getBuffsAt(charId: string, time: number): Buff[] {
    const schedule = this.buffSchedule.get(charId) ?? []
    return schedule
      .filter(s => time >= s.timeStart && time < s.timeEnd)
      .map(s => s.buff)
  }

  /** 将 Buff 中的 statBonuses 应用到角色属性 */
  applyBuffStats(
    baseStats: Record<string, number>,
    charId: string,
    time: number,
  ): Record<string, number> {
    const activeBuffs = this.getBuffsAt(charId, time)
    return applyBuffStatBonuses(baseStats, activeBuffs, charStatConfig)
  }
}
```

## 九、风险与注意事项

### 9.1 性能风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 大型时间线演算耗时 | UI 卡顿 | 使用 Web Worker 或在 requestAnimationFrame 中分片计算 |
| 伤害曲线高频采样 | 渲染慢 | 降采样（每 0.1s 一个采样点足够） |
| Buff 频繁启停 | 查找开销 | 使用线段树/区间树优化 Buff 查询 |

### 9.2 数据一致性风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 后端 Gain 与前端 Buff 格式不匹配 | 无法解析 | 使用统一映射表 + 运行时类型校验 |
| 属性计算入口不统一 | 三系统结果不一致 | 强制使用 `calcFinalStats()` 作为唯一入口 |
| Buff 替换逻辑（潜能升级） | 旧数据失效 | 在 `TimelineBuffManager` 中实现替换检测 |

### 9.3 现有行为保留

- **不删除** `calcDamage()` 和 `DamageInput`（保持向后兼容）
- **不删除** `staggerEngine.ts`（保持 CurvePanel 的现有渲染逻辑，逐步迁移）
- **不修改** API 层和数据库结构（后端无需改动）
- **不修改** 现有的 `teamEngine.ts` 签名（只是内部实现替换）
